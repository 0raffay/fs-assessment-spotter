# Frontend structure (`apps/web`)

React 19 + Vite + TypeScript (strict), with Tailwind CSS v4, shadcn/ui, TanStack Query, axios,
zod, MSW, MapLibre (`react-map-gl`) and `motion`.

```
apps/web/
├── e2e/                             Playwright end-to-end tests (run against the mocked app)
├── public/mockServiceWorker.js      Generated by `msw init` — never edit
└── src/
    ├── main.tsx                     Starts MSW (when enabled), then renders <App/>
    ├── index.css                    Tailwind + design tokens (see DESIGN.md)
    ├── app/                         Wiring only: providers, router
    ├── components/
    │   ├── ui/                      shadcn components — added with the CLI, never edited
    │   └── <shared>.tsx             Feature-agnostic UI (risk badge, logo…)
    ├── lib/
    │   ├── api/
    │   │   ├── client.ts            The axios agent + ApiError
    │   │   ├── endpoint.ts          defineEndpoint / callEndpoint (typed + validated)
    │   │   └── query-keys.ts        createQueryKeys()
    │   ├── env.ts                   Typed, validated import.meta.env
    │   ├── format.ts                Durations, miles, times in a place's zone, weather units
    │   ├── risk.ts                  Risk/condition metadata and helpers
    │   ├── create-strict-context.ts Typed context factory
    │   └── routes.ts                ROUTES: every page URL, defined once
    ├── mocks/                       MSW — delete this folder when the backend is live
    │   ├── engine/                  Deterministic mock data (geo, weather, rules, trip, heatmap)
    │   ├── mock-endpoint.ts         mockEndpoint(): MSW handler from an endpoint definition
    │   ├── handlers.ts              All feature mock handlers
    │   ├── browser.ts / server.ts   Worker for the browser, server for Vitest
    ├── types/                       Types shared by several features
    │   ├── domain.ts                zod schemas + inferred types (Route, Checkpoint, RiskLevel…)
    │   ├── api.ts                   HttpMethod, ApiErrorBody, ApiErrorKind
    │   └── utility.ts               Generic helpers (Brand, Prettify, RecordOf, ById…)
    ├── features/<feature-name>/     One folder per feature (below)
    └── tests/setup.ts               Vitest setup (jest-dom + MSW server)
```

## A feature folder

```
features/<feature-name>/
├── index.ts                         Public exports — other features import only from here
├── types/
│   └── index.ts                     Feature-only schemas and types (shared ones live in src/types)
├── page/index.tsx                   The routed page (only if the feature has a URL)
├── components/
│   ├── <component>.tsx
│   └── tests/<component>.test.tsx
├── context/
│   └── <feature>-context.tsx        State shared by the feature's components
├── hooks/                           Feature hooks that aren't data fetching (optional)
└── api/
    ├── <feature>.endpoints.ts       defineEndpoint(...) — the contract for this feature
    ├── <feature>.service.ts         class XService { static … } — calls callEndpoint
    ├── <feature>.keys.ts            Query keys via createQueryKeys()
    ├── <feature>.api.ts             React Query hooks (useX…)
    ├── <feature>.mock.ts            MSW handlers for this feature's endpoints
    └── tests/
```

Each feature also has a doc in `docs/features/<feature>.md`.

### The data flow

```
component → <feature>.api.ts (hooks) → <feature>.service.ts → callEndpoint → axios → /api
                    ↑                                              ↑
             <feature>.keys.ts                        <feature>.endpoints.ts (zod)
                                                                   ↓
                                                     <feature>.mock.ts (MSW, when enabled)
```

| File                     | Holds                                                       |
| ------------------------ | ----------------------------------------------------------- |
| `<feature>.endpoints.ts` | Endpoint definitions: method, path, query/body/response zod |
| `<feature>.service.ts`   | `class XService { static … }`, one method per endpoint      |
| `<feature>.keys.ts`      | Query keys built with `createQueryKeys('<feature>')`        |
| `<feature>.api.ts`       | `useX…` hooks wrapping the service with TanStack Query      |
| `<feature>.mock.ts`      | `mockEndpoint(endpoint, resolver)` handlers                 |

Rules:

- **Components only import hooks** from `<feature>.api.ts`, never services or axios.
- **Services have no React.** Static methods that call `callEndpoint(endpoint, { query, body })`.
- **Every request and response is validated** with the endpoint's zod schemas. A bad response
  becomes `ApiError` with `kind: 'invalid_response'`, not a crash deep in a component.
- **Errors are `ApiError`** (`kind`, `status`, `body`, `userMessage`).
- **Mocks never leak.** Services don't know mocks exist; MSW intercepts at the network level.

## Types

- **Shared types** (used by two or more features) live in `src/types/`. Domain types are inferred
  from zod schemas (`type Route = z.infer<typeof routeSchema>`), so runtime checks and types can't
  drift.
- **Feature types** live in `features/<feature>/types/index.ts`.
- **Prefer generics over duplication:** `RiskRecord<T>`, `ConditionRecord<T>`, `RecordOf<K, V>`,
  `EndpointRequest<E>`, `EndpointResponse<E>`, `createStrictContext<T>()`, `ById<T>`.
- **Branded ids** (`RouteId`, `CheckpointId`, `PlaceId`) stop ids of different things being mixed up.
- TypeScript runs with `strict`, `noUncheckedIndexedAccess` and `noImplicitOverride`.

## Mocks and the real API

- **Development:** mocks are on by default (`VITE_ENABLE_MOCKS` defaults to `true` in dev). Set
  `VITE_ENABLE_MOCKS=false` in `apps/web/.env` to use the Django API through the Vite proxy. No
  feature code changes.
- **Production builds:** mocks are off by default, so a deploy can't ship fake data
  (`docs/deployment.md`).
- **Tests:** Vitest always uses the mocks. Playwright runs against the mocks (`pnpm test:e2e`) or
  the real API with offline providers (`pnpm test:e2e:django`).
- The mocks (`src/mocks/`, `*.mock.ts`) stay as hermetic test fixtures.

## Tests

- **Unit and component tests:** Vitest + Testing Library, in a `tests/` folder next to the code.
  They use the same MSW handlers as the browser.
- **End-to-end:** Playwright in `apps/web/e2e/`, against the mocked app (MSW in the browser), in
  two projects: `desktop` (1440×900) and `phone` (Pixel 7). Specs cover:
  - Planning: validation, three ranked routes, route selection, restoring from a shared link.
  - Map tools: layers, legend, checkpoint list and card, filters, the desktop risk profile.
  - The forecast slider, theme and help, and a map render with no page errors.
  - `pnpm test:e2e` starts its own Vite server on port 5190 (reusing one locally).
  - `PW_CHANNEL=msedge` (or `chrome`) runs on an installed browser instead of Playwright's
    bundled one; otherwise run `pnpm --filter web exec playwright install chromium` once.
  - The browser time zone is pinned to America/Chicago so clock labels are stable.

## Page routes: `lib/routes.ts`

`ROUTES` is the only place a URL string is written. Each entry is a function; calling it without
arguments gives the router pattern, and with arguments gives a real URL.

## Naming conventions

| Thing             | Convention                                | Example                     |
| ----------------- | ----------------------------------------- | --------------------------- |
| Files and folders | **kebab-case**                            | `route-card.tsx`            |
| Feature api files | `<feature>.<role>.ts`                     | `routes.endpoints.ts`       |
| Components        | PascalCase, named export                  | `export function RouteCard` |
| Hooks             | `use` + camelCase                         | `useTripPlan`               |
| Service classes   | PascalCase + `Service`                    | `RoutesService`             |
| Query key objects | camelCase + `Keys`                        | `routesKeys`                |
| zod schemas       | camelCase + `Schema`                      | `tripPlanSchema`            |
| Constants         | UPPER_SNAKE_CASE                          | `RISK_LEVELS`               |
| Tests             | `tests/<file>.test.ts(x)` beside the code | `lib/tests/format.test.ts`  |

Other conventions: named exports only; import with the `@/` alias; features import each other only
through `index.ts`; shadcn components come from the CLI (`pnpm dlx shadcn@latest add <name>`).
